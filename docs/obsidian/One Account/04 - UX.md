# UX

The member should feel: **I have a Gutguard account.** Not three memberships.

## Login

Same behavior on every origin (event staff must not depend on Lifestyle being up):

- Field: Username or email
- Password
- No `@` → OneGrinders (local-first mirror, then API, then backup)
- Email → Supabase password

Land:

| Arrived from | Go |
|---|---|
| Lifestyle | Door card if unclaimed, else `/app/health` |
| GEMA + `redirectTo` | That path |
| GEMA, distributor | GEMA dashboard |
| GEMA, person but not distributor | Lifestyle hub (after Change 5); until then existing GEMA onboarding |
| Academy | `/academy` |

New login UI follows Design System (Lifestyle dialect). GEMA may keep its current login layout in v1 if fields and behavior match. Academy chairman dashboard is not a login screen — do not restyle it in these Changes.

## Registration

One form, one place: Lifestyle `/register`. Name, mobile, email, password, then
the 6-digit code Staging emails.

- **Spokes have no sign-up form.** Their login pages link to Lifestyle register
  with a `returnTo`, and the member lands back where they started.
- **A guild member never registers.** "Already a OneGrinders member? Sign in
  with your username." Their first visit creates the product row (Change 4) —
  no second account, no second form.
- **Event registration is not account registration.** Ginhawa `/register/<event>`
  captures a prospect with a sponsor `ref` and stays in GEMA. It creates no Auth
  user; conversion does that later (D9, D13).

## Hub chrome (Change 5)

Lifestyle shell gains Events → GEMA and Academy → Academy. Spokes gain a Gutguard home link. Settings for name/mobile live in Lifestyle.

## First visit

OneGrinders member opening Lifestyle: create card from existing name. No second register.  
Ginhawa registrant opening GEMA/Academy later: same email/password, no second account.
